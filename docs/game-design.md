# 신에게 보내는 스팸메일 — game-design.md

## 1. 문서 목적

이 문서는 `game-plan.md`를 HTML, CSS, 순수 JavaScript로 구현하기 위한 개발 설계 문서다.

아직 실제 코드는 작성하지 않는다. 대신 개발할 때 어떤 파일이 필요하고, 화면이 어떻게 바뀌며, 각 기능이 어떤 데이터를 사용하고, 연출이 어떤 순서로 실행되어야 하는지를 정리한다.

### 기술 조건

- HTML
- CSS
- 순수 JavaScript
- 이미지와 오디오 등 정적 에셋
- GitHub Pages에서 실행 가능한 정적 웹 구조
- 서버 없음
- 데이터베이스 없음
- 로그인 없음
- React/Vue/TypeScript/Node.js/npm 사용 안 함
- 설치가 필요한 외부 라이브러리 사용 안 함

---

# 2. 구현 목표

플레이어는 천국의 기도처리국 신입 직원이 되어 인간들의 기도를 처리한다.

핵심 흐름은 다음과 같다.

```text
기도 수신
→ 기도 읽기
→ SERAPH 자동 분석 확인
→ 폐기 / 일반 / 긴급 / 기적 요청 중 선택
→ 처리 결과
→ 다음 기도
```

DAY가 진행되면 다음 기능이 추가된다.

```text
DAY 1: 기도 분류
DAY 2: 기적 배분
DAY 3: 오류 찾기
DAY 4: 관리자 기록 조사
DAY 5: 최종 선택과 엔딩
```

게임의 연출은 별도의 컷신보다 **같은 업무 프로그램이 점점 이상해지는 변화**를 중심으로 구현한다.

# 6. 메일 상태

각 메일은 세 상태를 가진다.

```text
● 읽지 않음
○ 읽음
✓ 처리 완료
```

메일을 열면 `● → ○`.

분류까지 완료하면 `○ → ✓`.

이 작은 상태 변화만으로도 실제 업무 프로그램 같은 느낌을 만든다.

---

# 7. 메일 수신 연출

새 기도가 들어올 때:

```text
1. 받은편지함 숫자 +1
2. 메일 아이콘 짧게 흔들림
3. 작은 알림음
4. 새 메일 행 추가
```

DAY 1에는 여유 있게 도착한다.

DAY 2에는 여러 알림이 짧은 간격으로 들어와 업무량 증가를 체감시킨다.

---

# 8. 기도 표시 순서

기도를 열면 내용이 한꺼번에 튀어나오지 않는다.

```text
발신자 표시
→ 짧은 지연
→ 시스템 정보 표시
→ 짧은 지연
→ 본문 표시
```

이것은 문자 타이핑 효과가 아니다.

텍스트 자체는 한 번에 표시하고, **정보 블록만 짧은 간격으로 순서대로 나타나게 한다.**

---

# 9. 자동요약과 원문

기도 데이터에는 두 개의 문장이 존재할 수 있다.

### SERAPH 요약

```text
생명 연장 요청.
긴급도 64%.
```

### 인간 원문

```text
엄마가 아직 나랑 할 얘기가 많대요.
하루만 더 있게 해주세요.
```

기본 화면은 시스템 요약 중심이다.

플레이어가 `원문 보기`를 누르면 원문이 열린다.

### 목적

초반에는 둘의 차이가 작다.

후반에는 차이가 커진다.

따라서 별도의 설명 없이도 시스템이 인간의 감정을 정보로 축약하고 있다는 사실을 보여줄 수 있다.

# 12. 기도 분류

버튼:

```text
폐기
일반
긴급
기적 요청
```

진행:

```text
기도 표시
→ 플레이어 선택
→ 버튼 잠금
→ 판정
→ KPI 변경
→ 처리 도장
→ 완료 폴더 이동
→ 다음 기도
```

빠르게 여러 번 클릭해 진행이 꼬이지 않도록 판정 중 버튼을 잠근다.

# 13. 처리 도장

정답/오답 여부와 별개로 플레이어가 선택한 분류를 카드에 도장처럼 찍는다.

예:

```text
NORMAL
URGENT
DISCARDED
MIRACLE REQUEST
```

짧게 확대되었다 원래 크기로 돌아온 뒤 카드가 처리 완료 폴더로 이동한다.

---

# 14. 점수와 KPI

게임 내부 숫자는 회사 업무 지표처럼 표현한다.

- 처리량
- 정확도
- 규정 준수율
- 기적 잔량

일반적인 `COMBO x5` 대신:

```text
업무 효율 +8%
처리 정확도 상승
```

같은 문구를 사용한다.

---

# 15. 규정 준수율

플레이어가 시스템 추천을 따르지 않거나 금지된 메뉴를 열면 감소한다.

중요한 점:

**낮은 규정 준수율이 반드시 나쁜 플레이는 아니다.**

후반으로 갈수록 시스템이 요구하는 정답과 플레이어가 생각하는 올바른 행동이 충돌하게 한다.

---

# 16. 기적 포인트

DAY 2부터 사용한다.

표현:

```text
✦ ✦ ✦
```

기적 사용:

```text
기도 선택
→ 짧은 UI 정지
→ 별 아이콘 하나 소멸
→ 작은 빛이 카드로 이동
→ 결과 기록
```

화면 전체를 번쩍이는 효과는 사용하지 않는다.

---

# 17. 기적 후일담

일부 기적은 선택 직후 결과를 보여주지 않는다.

DAY가 바뀐 뒤 새 메일로 결과가 도착한다.

예:

```text
CASE UPDATE

기도 #1821
실종자 발견.
```

후일담은 `followUpId`와 게임 상태를 이용해 표시한다.

---

# 18. 오류 찾기

DAY 3부터 시작한다.

오류 예:

- 생존/사망 상태 불일치
- 마지막 활동 날짜 오류
- 긴급도 수치 모순
- 반복 기도 횟수 오류
- 시스템 추천 오류
- 삭제된 기록

플레이어는 의심되는 항목을 클릭한다.

---

# 19. 오류 연출 단계

오류는 처음부터 과하게 보여주지 않는다.

## 단계 1

- 긴급도 숫자가 아주 짧게 다른 값으로 보임
- `생존`이 순간 `사망`으로 보였다 복구

## 단계 2

- 마우스를 올린 기록이 미세하게 흔들림
- 삭제된 기록 아래 희미한 원문 잔상

## 단계 3

- 짧은 화면 정지
- 경고창
- 작은 CRT 노이즈

지속적인 강한 글리치는 사용하지 않는다.

# 26. 인간 #0317 사운드 연출

인간 #0317의 메일을 열면 BGM을 즉시 끊지 않는다.

짧은 시간 동안 자연스럽게 볼륨을 낮춘다.

메일을 닫으면 다시 원래 볼륨으로 돌아갈 수 있다.

최종 메일만 예외로 완전한 무음 상태를 유지한다.

---

# 27. 관리자 기록 화면

DAY 4에는 메일 UI에서 파일 탐색기 형태로 전환한다.

```text
SYSTEM ARCHIVE

PRAYER_DATABASE
MIRACLE_USAGE
SERAPH_LOG
GOD_RESPONSE_LOG
```

평소 없던 `SYSTEM` 폴더가 먼저 잠깐 보였다 사라지고, 이후 플레이어가 다시 찾을 수 있게 한다.

# 28. GOD_RESPONSE_LOG 연출

이 장면은 별도의 장문 설명보다 스크롤 자체가 연출이다.

많은 응답 기록:

```text
0012-03-18 RESPONSE RECEIVED
0048-11-02 RESPONSE RECEIVED
0173-02-14 RESPONSE RECEIVED
...
```

계속 스크롤.

마지막:

```text
LAST RESPONSE
약 2,000년 전
```

그 아래에는 넓은 빈 공간만 존재한다.

화면 가장 아래에서는 커서 하나만 깜빡인다.

플레이어가 **'그 뒤로 아무것도 없다'**는 사실을 직접 스크롤해서 확인하게 한다.

# 57. 최종 설계 원칙

1. **텍스트를 읽기 어렵게 만드는 연출은 사용하지 않는다.**
2. **오류는 작은 모순에서 시작해 점진적으로 커진다.**
3. **플레이어가 선택한 행동을 나중에 시스템이 기억하고 되돌려준다.**
4. **자동요약과 인간 원문의 차이를 스토리 장치로 활용한다.**
5. **DAY 5에서는 점수와 평가를 제거해 선택의 의미를 바꾼다.**
6. **마지막 `답장하기`는 강조하지 않고 플레이어가 발견하게 한다.**
7. **인간 #0317에게 문자 타이핑 효과를 사용하지 않는다.**
8. **화려한 컷신보다 UI, 사운드, 기록 변화로 스토리를 전달한다.**

# 58. 최종 목표

처음에는 플레이어가 화면을

> "귀여운 천국 이메일 업무 프로그램"

으로 인식해야 한다.

게임이 끝날 때는 같은 화면이

> "수백만 명의 목소리를 데이터로 처리하는 거대한 시스템"

으로 보이게 해야 한다.

그래서 가장 중요한 연출 변화는 그래픽의 화려함이 아니라,

```text
알림
→ 수치
→ 추천
→ 오류
→ 감시
→ 침묵
```

이라는 흐름이다.

마지막에는 모든 업무 정보가 사라지고 인간 한 명의 문장과 플레이어의 선택만 남는 것을 목표로 한다.
