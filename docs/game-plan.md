# 신에게 보내는 스팸메일 — 웹게임 제작 플랜

## 1. 프로젝트 개요

### 게임 제목
**신에게 보내는 스팸메일**  
영문 가제: **SPAM TO GOD**

### 장르
- 캐주얼 판별 게임
- 내러티브 시뮬레이션
- 업무/사무실 시뮬레이션
- 선택형 스토리 게임

### 플랫폼
- PC 웹 브라우저 우선
- 모바일 브라우저 대응 가능
- HTML / CSS / JavaScript 기반
- 서버, 로그인, 데이터베이스 없이 실행 가능한 싱글 플레이 게임

### 권장 플레이 타임
- 1회 약 **15~25분**
- 엔딩 3종
- 재플레이 시 다른 선택과 결과 확인 가능

### 핵심 한 줄
> 천국의 기도처리국 신입 천사가 되어 인간들의 기도를 분류하고, 제한된 기적을 배분하다가 '신은 정말 기도를 듣고 있는가?'라는 진실과 마주하는 게임.

---

# 2. 핵심 재미

이 게임의 핵심은 단순히 이메일을 읽고 버튼을 누르는 것이 아니다.

플레이어는 처음에는 회사 규정에 따라 효율적으로 기도를 처리하지만, 게임이 진행될수록 규칙과 인간의 사연 사이에서 갈등하게 된다.

게임의 재미는 크게 세 가지다.

1. **빠른 판별**
   - 기도 내용을 읽고 규정에 따라 분류한다.
2. **오류 조사**
   - 자동 분류 시스템이나 기록에서 이상한 부분을 찾아낸다.
3. **제한된 자원 배분**
   - 하루에 사용할 수 있는 적은 수의 기적 포인트를 누구에게 사용할지 결정한다.

후반부에는 이 세 가지 시스템이 모두 스토리 선택으로 연결된다.

# 3. 목표 분위기

### 초반
- 귀엽고 밝은 천국 오피스
- 회사 업무 패러디
- 가벼운 개그
- 레트로 이메일 프로그램 느낌

### 중반
- 반복되는 업무
- 조금씩 이상해지는 시스템
- 기도 내용이 점점 무거워짐
- 사무실의 밝은 외형과 내용의 대비

### 후반
- 정적인 분위기
- 음악과 UI가 미묘하게 깨지기 시작
- '신'에 대한 의문
- 플레이어의 선택이 중요해짐

### 추천 비주얼 방향
- 픽셀아트
- CRT/레트로 컴퓨터 UI
- 크림색 + 하늘색 + 금색 계열의 천국 오피스
- 후반으로 갈수록 채도 감소
- 시스템 오류 시 적색 또는 검은색 노이즈
- 초반에는 UI가 지나치게 친절하고 명랑하게 느껴지도록 구성
- 후반으로 갈수록 점수·평가·추천 등 '게임적인 UI'를 하나씩 제거
- 오류는 처음부터 큰 글리치로 보여주지 않고 숫자, 문구, 기록이 잠깐 어긋나는 방식으로 시작

# 4. 플레이어 역할

플레이어는 천국의 **기도처리국 제7분류과**에 새로 입사한 계약직 천사다.

직무는 인간들이 보내는 기도를 읽고 아래 항목으로 분류하는 것.

- 폐기
- 일반
- 긴급
- 기적 요청

플레이어의 이름과 성별은 직접적으로 정하지 않는다.

게임 내에서는 주로 다음과 같이 호칭한다.

- 신입
- 7번 사원
- 신규 계약직

이를 통해 플레이어가 캐릭터에 쉽게 이입하도록 한다.

진실 엔딩에서는 플레이어의 선택에 따라 처음으로 시스템에 의문을 품는다.

# 6. 전체 스토리 구조

게임은 **5일간의 근무**로 진행한다.

# DAY 1 — 첫 출근

## 목적
- 게임 조작 학습
- 세계관 소개
- 가벼운 분위기 형성

## 연출
- 새 기도가 오면 받은편지함 숫자가 증가하고 메일 아이콘이 짧게 흔들림
- 기도는 발신자 → 제목/분류 정보 → 본문 순으로 짧은 간격을 두고 표시
- 처리 완료 시 카드에 `NORMAL`, `URGENT` 등의 업무 도장이 찍힌 뒤 처리 완료 폴더로 이동
- SERAPH는 `"오늘도 효율적인 근무 되세요!"`처럼 지나치게 친절한 문구를 사용
- 밝은 BGM, 맑은 클릭음, 움직이는 사무실 NPC로 활기찬 첫 출근 분위기 형성

## 등장 기도 예시

> "오늘 발표 안 시키게 해주세요."

> "좋아하는 사람이 먼저 연락하게 해주세요."

> "시험 문제 3번 정답만 알려주세요."

> "우리 강아지가 건강하게 오래 살게 해주세요."

## 게임
빠른 분류 게임 중심.

## 플레이어가 배우는 규칙
- 개인적 사소한 부탁 → 일반 또는 폐기
- 생명 위험 → 긴급
- 현실을 직접 바꾸는 요청 → 기적 요청

마지막에 인간 #0317의 첫 기도가 등장한다.

# DAY 2 — 업무 폭주

## 목적
- 게임 속도 증가
- 기적 포인트 시스템 도입

## 연출
- 메일 알림이 조금 더 자주 겹쳐 들리고 받은편지함 숫자가 빠르게 증가
- 기존의 점수 표현을 세계관에 맞춰 `처리량 / 정확도 / 규정 준수율` KPI처럼 강조
- 기적 포인트는 별빛 아이콘 3개로 표시하고 사용할 때 실제로 하나씩 빛이 꺼짐
- 기적 사용 직후 0.5초 정도 UI와 BGM이 잠깐 정지한 뒤 별빛 효과와 함께 처리
- 일부 기적의 결과는 즉시 보여주지 않고 다음 DAY의 후일담 메일로 전달

기도가 빠르게 쌓이기 시작한다.

미카가 말한다.

> "월요일은 항상 이래요."

### 새로운 게임
기적 배정.

플레이어에게 **기적 포인트 3개**가 주어진다.

여러 요청 중 최대 3개만 선택 가능.

여기서 처음으로 정답이 없는 선택을 경험한다.

# DAY 3 — 분류 오류

## 목적
- 오류 찾기 미니게임 추가
- 메인 미스터리 시작

## 연출
- SERAPH의 친절한 문구가 `"규정에 따라 처리하십시오."`처럼 사무적으로 변하기 시작
- 긴급도나 상태 수치가 아주 짧게 다른 값으로 보였다가 원래 값으로 돌아오는 오류 발생
- 일부 기록에 마우스를 올리면 삭제선이나 희미한 원문 잔상이 나타남
- 오류 발견 순간 0.2~0.3초 화면이 정지하고 짧은 노이즈음 출력
- 인간 #0317의 메일을 열면 BGM 볼륨이 낮아져 문장에 집중하게 함

인간 #0317의 기도가

**[일반 / 긴급도 13%]**

로 자동 분류되어 있다.

플레이어가 기록을 클릭하면 이상한 점을 발견한다.

- 이전 기도 기록이 일부 삭제됨
- 긴급도 수치가 앞뒤와 맞지 않음
- 일부 발신자의 생존 정보가 오류

### 새로운 게임
**오류 찾기**

시스템 화면 안에서 잘못된 정보를 클릭한다.

예:

- 날짜 오류
- 발신자 상태 불일치
- 분류 코드 불일치
- 이전 기록과 모순

# DAY 4 — 신은 어디에 있는가

## 목적
- 세계관의 진실 공개

## 연출
- 사무실 배경의 NPC 수가 줄고 창밖 하늘의 채도가 낮아짐
- 평소 없던 `SYSTEM` 폴더가 잠깐 나타났다 사라진 뒤 조사 가능 상태가 됨
- 오래된 시스템 기록일수록 UI가 낡고 단순한 형태로 변화
- `GOD_RESPONSE_LOG`는 긴 기록을 스크롤하게 한 뒤 마지막 응답 이후 넓은 공백만 남겨 '응답의 부재'를 시각적으로 표현
- 마지막 로그 아래에는 입력을 기다리는 듯한 커서만 계속 깜빡임
- SERAPH는 플레이어의 실제 처리 기록을 바탕으로 `"최근 긴급 요청 규정 이탈률"` 같은 문구를 표시하여 감시받는 느낌을 줌

플레이어는 관리자 메뉴에 접근한다.

숨겨진 파일:

`GOD_RESPONSE_LOG`

마지막 응답:

**약 2,000년 전**

그 이후 직접적인 신의 응답 기록이 없다.

기도처리국은 사실 신의 명령을 전달하는 기관이 아니라,

**천사들이 제한된 기적 에너지를 자체적으로 분배하면서 신이 아직 응답하고 있는 것처럼 유지하는 기관**이었다.

가브리엘이 등장한다.

> "중요한 건 신이 대답하는지가 아닙니다."

> "인간들이 대답이 있다고 믿는 것이죠."

플레이어는 계속 근무할지 시스템을 조사할지 선택한다.

# DAY 5 — 마지막 기도

시작부터 UI가 평소와 다르다.

메일이 거의 없다.

배경 음악도 매우 조용하다.

## 연출
- 점수, 업무 평가, 콤보, 추천 분류 등 게임적인 정보가 하나씩 사라짐
- 사무실 NPC가 거의 보이지 않고 벽시계가 멈춰 있음
- 인간 #0317의 메일을 여는 순간 남아 있던 BGM도 완전히 멈춤
- 자동 분석에는 차가운 요약문이 표시되고, `원문 보기`를 누르면 실제 인간의 문장이 따로 나타남
- 기존 4개 분류 버튼이 먼저 나타난 뒤 잠시 후 화면 아래에 작은 `답장하기` 버튼이 조용히 추가됨
- `답장하기`는 천국 시스템 버튼과 다른 단순한 인간 메신저 스타일로 표현

인간 #0317의 마지막 기도 등장.

> "엄마는 오늘 죽었어요."

잠시 후 다시 한 통.

> "마지막으로 하나만 물어볼게요."

> "거기 정말 누가 있기는 한가요?"

화면에 기존 버튼 등장.

- 폐기
- 일반
- 긴급
- 기적

그리고 몇 초 뒤 화면 아래 작은 버튼이 나타난다.

**답장하기**

여기서 최종 선택.

# 9. 엔딩 C — 답장

### 조건
숨겨진 **답장하기** 버튼 선택.

천국의 규칙상 인간에게 직접 답장하는 것은 금지.

텍스트 입력창이 등장한다.

플레이어가 직접 답장을 적거나 기본 문장을 선택.

추천 기본 문장:

> "응."

> "듣고 있어."

잠시 후 인간 #0317의 답장.

> "그럼 됐어요."

시스템 경고가 여러 개 등장하지만 하나씩 꺼진다.

마지막에는 빈 메일 화면만 남는다.

### 마지막 문구

> 응답은 기적이 아니었다.

BLACK OUT.

# 25. 연출 디테일 설계

게임의 연출은 화려한 컷신보다 **업무용 프로그램 자체가 서서히 변하는 방식**을 우선한다.

## 25.1 메일과 업무 피드백

- 새 기도 수신 시 받은편지함 숫자 증가 + 작은 알림음 + 메일 아이콘 1회 흔들림
- 읽기 전 `●`, 읽은 후 `○`, 처리 후 `✓`로 메일 상태 표시
- 분류 완료 시 카드 위에 업무용 도장이 찍힌 뒤 처리 완료 폴더로 이동
- 정답/오답은 거대한 성공·실패 연출 대신 작은 시스템 메시지와 효과음으로 처리
- 연속 정답은 `COMBO` 대신 `업무 효율 상승`, `처리 정확도 상승`처럼 회사식 표현 사용

## 25.2 자동요약과 인간 원문

SERAPH는 인간의 기도를 감정이 제거된 데이터로 요약한다.

예:

```text
SERAPH SUMMARY
분류: 생명 연장 요청
긴급도: 64%
```

플레이어가 `원문 보기`를 누르면 실제 기도 내용이 나타난다.

```text
"엄마가 아직 나랑 할 얘기가 많대요.
하루만 더 있게 해주세요."
```

초반에는 요약과 원문의 차이가 작지만 후반으로 갈수록 차이를 크게 만들어 시스템의 비인간성을 강조한다.

## 25.3 SERAPH의 변화

DAY 1:
> 오늘도 효율적인 근무 되세요!

DAY 3:
> 권고 분류를 확인하십시오.

DAY 4:
> 직원 #07의 처리 패턴을 분석 중입니다.

DAY 5:
> 규정 위반이 감지되었습니다.

같은 시스템이 점점 친절함을 잃고 통제적인 존재처럼 보이게 한다.

## 25.4 시스템 오류

오류는 단계적으로 강해진다.

### 초기
- 긴급도 숫자가 순간적으로 다른 값으로 표시
- `생존`이 한순간 `사망`으로 바뀌었다 복구
- 폴더 이름이 잠시 달라짐

### 중반
- 삭제된 기록 아래 흐릿한 원문 잔상
- 마우스를 올린 기록만 흔들림
- 시스템 추천과 실제 규정이 불일치

### 후반
- 경고창 중첩
- UI 일부 기능 정지
- 텍스트 위치가 미세하게 어긋남
- 짧은 CRT 노이즈

가독성을 해치는 지속적인 글리치는 사용하지 않는다.

## 25.5 캐릭터 변화

### 미카
- DAY 1: 웃음, 적극적으로 설명
- DAY 2: 평소와 비슷함
- DAY 3: 오류 이야기를 하면 시선을 피함
- DAY 4: 진지한 표정, 말줄임표 증가
- DAY 5: 거의 등장하지 않거나 짧은 메시지만 남김

같은 말도 문장부호로 분위기를 변화시킨다.

```text
DAY 1: "괜찮아요!"
DAY 4: "...괜찮아요."
```

### 가브리엘
가브리엘이 등장하면 다른 UI 버튼을 잠시 잠그고 대화창을 중앙에 띄워 통제력을 표현한다.

## 25.6 사무실 배경 변화

DAY가 진행될수록 배경도 조용히 변한다.

- DAY 1: 많은 천사 NPC, 맑은 하늘
- DAY 2: 바쁜 사무실
- DAY 3: 일부 빈 자리, 노을
- DAY 4: NPC 감소, 흐린 하늘
- DAY 5: 거의 빈 사무실, 멈춘 벽시계

큰 설명 없이도 플레이어가 분위기 변화를 느끼게 한다.

## 25.7 사운드 변화

같은 효과음을 DAY별로 조금씩 변화시킨다.

- 메일 알림음은 후반으로 갈수록 한 음이 빠지거나 피치가 낮아짐
- 클릭음은 맑은 소리에서 건조한 기계음으로 변화
- DAY 1 BGM은 멜로디와 리듬이 모두 존재
- DAY 3부터 일부 악기 레이어 제거
- DAY 4는 앰비언트 중심
- DAY 5 마지막 기도에서는 완전한 무음

특히 인간 #0317 메일을 열 때마다 BGM을 자연스럽게 낮춘다.

## 25.8 기적 연출

기적 포인트는 `✦ ✦ ✦` 형태의 빛나는 아이콘으로 표현한다.

사용 시:

```text
기도 선택
↓
UI 짧게 정지
↓
별 아이콘 하나 소멸
↓
작은 빛이 기도 카드 쪽으로 이동
↓
처리 완료
```

과도한 화면 플래시는 사용하지 않는다.

일부 결과는 바로 알려주지 않고 이후 메일로 전달한다.

## 25.9 후일담

과거에 처리한 선택이 며칠 뒤 다시 등장한다.

예:

```text
기도 #1821
상태 업데이트

실종자 발견.
```

또는

```text
기도 #922
기적 미배정

후속 기록 없음.
```

선택의 결과를 설명창이 아니라 업무 기록으로 전달한다.

## 25.10 플레이어 행동 감시

SERAPH는 실제 플레이 기록을 분석한다.

예:

```text
직원 #07

평균 처리 시간: 4.8초
규정 준수율: 83%
시스템 추천 거부: 7회
긴급 요청 수동 변경: 4회
```

플레이어가 자신의 행동이 기록되고 있었다는 느낌을 준다.

## 25.11 DAY 5 UI 제거

DAY 5에서는 다음 요소를 순차적으로 제거한다.

1. 점수
2. 등급
3. 업무 효율
4. 처리 속도
5. SERAPH 추천 분류

마지막에는 사실상

- 인간의 기도
- 네 개의 분류 버튼
- 답장하기

만 남긴다.

이는 플레이어가 더 이상 '점수를 얻기 위해' 선택하지 않게 만드는 장치다.

## 25.12 마지막 `답장하기`

인간 #0317의 마지막 기도가 나타나도 처음에는 기존 네 버튼만 보인다.

```text
[폐기] [일반] [긴급] [기적 요청]
```

잠시 후 아주 작은 새로운 버튼이 화면 아래 나타난다.

```text
답장하기
```

- 깜빡이거나 강조하지 않음
- 효과음도 없음
- 천국 UI와 다른 단순한 디자인
- 마우스를 올렸을 때만 아주 약하게 밝아짐

플레이어가 시스템 밖의 선택을 **스스로 발견했다는 느낌**을 주는 것이 중요하다.

## 25.13 엔딩별 연출

### 회사원 엔딩
DAY 1과 거의 똑같은 업무 화면으로 돌아간다.

차이점은 플레이어의 직급뿐이다.

```text
제7분류과 팀장
```

받은편지함:

```text
8,213,921
```

게임 시작과 엔딩을 시각적으로 루프시킨다.

### 기적 엔딩
거대한 천상 효과보다 작은 별빛 하나를 사용한다.

`LIFE RESTORATION FAILED` 이후 시스템 화면보다 두 사람의 짧은 대화를 중심으로 표현한다.

### 답장 엔딩
답장창에는 미리 작성된 문장을 넣지 않는다.

빈 입력창과 깜빡이는 커서만 표시한다.

기본 문장을 선택할 수 있지만 직접 작성할 수도 있다.

답장을 보낸 뒤 여러 규정 위반 경고창이 나타났다가 하나씩 자연스럽게 꺼진다.

마지막에는 메일 화면도 사라지고 인간 #0317의

> "그럼 됐어요."

만 남긴다.

## 25.14 엔딩 크레딧

엔딩 크레딧 사이에 플레이어가 처리했던 기도 일부를 다시 보여준다.

가능하다면 일부 ID를 마지막에 실제 이름처럼 바꾸어 보여준다.

```text
인간 #0317
↓
서윤
```

이를 통해 게임 내내 사람을 번호와 데이터로 보았다는 사실을 마지막에 다시 체감하게 한다.

# 26. 추천 최종 방향

이 게임의 가장 중요한 요소는 **대규모 콘텐츠가 아니라 기도의 문장**이다.

따라서 그래픽을 지나치게 많이 제작하기보다

- UI
- 캐릭터 2~3명
- 텍스트
- 사운드
- 작은 애니메이션

에 집중하는 것이 좋다.

특히 초반에는 웃긴 기도를 많이 배치하고, 플레이어가 시스템에 익숙해진 뒤 점점 진지한 기도를 섞으면 후반부의 감정적 대비가 커진다.

또한 마지막 엔딩에서는 새로운 조작법을 추가하기보다, 지금까지 계속 사용해온 **'기도를 처리하는 버튼'을 누르지 않는 선택**을 만드는 것이 좋다.

게임 전체에서 플레이어가 배운 규칙을 마지막 순간에 스스로 어기게 만드는 것이 이 게임의 가장 중요한 연출 포인트다.
